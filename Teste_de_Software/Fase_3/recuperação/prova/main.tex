\begin{enumerate}[leftmargin=*]

\item \textbf{(1,0 ponto)} Qual situação indica uma má prática em automação?

\begin{enumerate}[label=(\Alph*)]
\item Isolamento dos testes.
\item Dados de teste independentes.
\item Dependência entre casos automatizados.
\item Integração com pipeline CI.
\item Execução automatizada em ambiente controlado.
\end{enumerate}

\vspace{0.2cm}

\item \textbf{(1,0 ponto)} Qual métrica é frequentemente utilizada para avaliar a eficácia de uma suíte automatizada?

\begin{enumerate}[label=(\Alph*)]
\item Quantidade de desenvolvedores.
\item Cobertura de testes.
\item Quantidade de reuniões realizadas.
\item Tamanho do backlog.
\item Quantidade de sprints executadas.
\end{enumerate}

\vspace{0.2cm}

\item \textbf{(1,0 ponto)} Qual prática favorece a manutenção de suítes automatizadas?
\begin{enumerate}[label=(\Alph*)]
\item Duplicação de código.
\item Uso de waits fixos em todos os testes.
\item Aplicação de padrões como Page Object Model.
\item Dependência entre casos de teste.
\item Armazenamento de credenciais diretamente no código.
\end{enumerate}

\vspace{0.2cm}

\item \textbf{(1,0 ponto)} Qual característica é mais importante para selecionar casos candidatos à automação?

\begin{enumerate}[label=(\Alph*)]
\item Casos executados raramente.
\item Casos altamente subjetivos.
\item Casos executados frequentemente e de forma repetitiva.
\item Casos sem resultados esperados definidos.
\item Casos ainda em fase de levantamento de requisitos.
\end{enumerate}

\vspace{0.2cm}

\item \textbf{(1,0 ponto)} Em uma estratégia baseada na Pirâmide de Testes, qual nível normalmente possui a maior quantidade de testes automatizados?

\begin{enumerate}[label=(\Alph*)]
\item Testes de Aceite.
\item Testes de Sistema.
\item Testes de Integração.
\item Testes de Unidade/Componente.
\item Testes Exploratórios.
\end{enumerate}

\vspace{0.2cm}

\item \textbf{(1,0 ponto)} Qual das alternativas representa um benefício típico da automação de testes?

\begin{enumerate}[label=(\Alph*)]
\item Eliminar completamente a necessidade de testes manuais.
\item Aumentar a cobertura e a repetibilidade dos testes.
\item Garantir que não existam defeitos no produto.
\item Reduzir a necessidade de análise de testes.
\item Eliminar a necessidade de validação dos requisitos.
\end{enumerate}

\item \textbf{(1,0 ponto)} Qual das seguintes práticas reduz mais efetivamente o custo de manutenção de testes automatizados?

\begin{enumerate}[label=(\Alph*)]
\item Automatizar apenas testes de interface gráfica.
\item Utilizar dados de teste fixos para todos os cenários.
\item Separar a lógica de teste da lógica de interação com a aplicação.
\item Executar testes apenas antes da release.
\item Executar todos os testes manualmente antes da automação.
\end{enumerate}

\item \textbf{(1,0 ponto)} Em um pipeline CI/CD, qual conjunto de testes deve fornecer feedback mais rápido aos desenvolvedores?

\begin{enumerate}[label=(\Alph*)]
\item Testes de aceite.
\item Testes exploratórios.
\item Testes de sistema completos.
\item Testes de unidade.
\item Testes de usabilidade.
\end{enumerate}

\item \textbf{(1,0 ponto)} Um teste automatizado falha porque um elemento da interface mudou de posição, embora a funcionalidade continue correta. Esse é um exemplo de:

\begin{enumerate}[label=(\Alph*)]
\item Defeito funcional.
\item Falso positivo.
\item Falso negativo.
\item Teste de regressão.
\item Erro de compilação.
\end{enumerate}

\item \textbf{(1,0 ponto)} Qual métrica isoladamente é MENOS adequada para medir o sucesso de uma iniciativa de automação?

\begin{enumerate}[label=(\Alph*)]
\item Tempo de execução da suíte.
\item Percentual de cobertura automatizada.
\item Quantidade de scripts automatizados.
\item Defeitos encontrados antes da produção.
\item Taxa de sucesso dos testes automatizados.
\end{enumerate}

\end{enumerate}
