\begin{enumerate}[leftmargin=*]

\item \textbf{(0,5 pontos)} Um sistema funciona corretamente sozinho, mas falha ao conectar com um banco de dados. Qual nível de teste detecta melhor isso?

\begin{enumerate}[label=(\Alph*)]
\item Unitário
\item Integração
\item Aceitação
\item Usabilidade
\item Sistema
\end{enumerate}

\vspace{0.2cm}

\item \textbf{(0,5 pontos)} Sistema atende regras corretas, mas fica lento com muitos usuários. Qual tipo de teste detecta isso?

\begin{enumerate}[label=(\Alph*)]
\item Funcional
\item Integração
\item Performance
\item Unitário
\item Caixa-Branca
\end{enumerate}

\vspace{0.2cm}

\item \textbf{(0,5 pontos)} Qual alternativa representa melhor a pirâmide de testes?

\begin{enumerate}[label=(\Alph*)]
\item Muitos E2E e poucos unitários
\item Apenas testes manuais
\item Muitos unitários e poucos E2E
\item Apenas integração
\item Caixa-Cinza
\end{enumerate}

\vspace{0.2cm}

\item \textbf{(0,5 pontos)} Um bug report sem passos para reprodução causa:

\begin{enumerate}[label=(\Alph*)]
\item Correção mais rápida
\item Melhor rastreabilidade
\item Dificuldade na análise
\item Mais cobertura
\item Falta de evidência
\end{enumerate}

\vspace{0.2cm}

\item \textbf{(0,5 pontos)} O programador escreve uma condição errada no código. Isso é um:

\begin{enumerate}[label=(\Alph*)]
\item Falha
\item Erro humano
\item Regressão
\item Performance
\item Relatório
\end{enumerate}

\vspace{0.2cm}

\item \textbf{(0,5 pontos)} Uma calculadora aceita apenas números inteiros entre -999 e 999. Utilizando análise de valor limite:

\begin{itemize}[itemsep=0pt, topsep=0pt]
    \item Determine os casos de teste mínimos;
    \item Identifique quais valores são válidos e inválidos.
\end{itemize}

\vspace{0.2cm}

\item \textbf{(0,5 pontos)} Um sistema possui as seguintes regras:

\begin{itemize}[itemsep=0pt, topsep=0pt]
    \item Apenas usuários administradores podem excluir contas;
    \item Usuários comuns não podem excluir contas;
    \item Contas bloqueadas não podem ser excluídas;
    \item Exclusão de conta exige confirmação.
\end{itemize}

Utilizando tabela de decisão:

\begin{itemize}[itemsep=0pt, topsep=0pt]
    \item Construa as combinações relevantes;
    \item Identifique ações esperadas;
    \item Determine quais regras podem ser eliminadas por redundância.
\end{itemize}

\item \textbf{(0,5 pontos)} Considere o seguinte pseudocódigo de uma calculadora:

\begin{lstlisting}[language=Python,
frame=single,
breaklines=true,
columns=fullflexible
]
def calcular(a, b, op):
    if op == "+":
        return a + b
    elif op == "-":
        return a - b
    elif op == "*":
        return a * b
    elif op == "/":
        if b == 0:
            return "Erro"
        return a / b
\end{lstlisting}

Responda:

\begin{itemize}[itemsep=0pt, topsep=0pt]
    \item quais caminhos precisam ser testados para cobertura de decisão;
    \item quais casos de teste mínimos atingem 100% de cobertura de decisão;
    \item qual técnica de teste caixa-preta também pode ser aplicada nesse código;
\end{itemize}

\vspace{0.2cm}

\item \textbf{(0,5 pontos)} Um sistema calcula desconto conforme a regra:

\begin{itemize}[itemsep=0pt, topsep=0pt]
    \item Até R\$100 → sem desconto
    \item Acima de R\$100 até R\$500 → 10%
    \item Acima de R\$500 → 20%
\end{itemize}

Utilizando a técnica de tabela de decisão:

\begin{itemize}[itemsep=0pt, topsep=0pt]
    \item Monte os cenários mínimos necessários;
    \item Identifique entradas, condições e saídas;
\end{itemize}
